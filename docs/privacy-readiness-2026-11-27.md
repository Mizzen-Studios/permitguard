## Live first-party findings

Official source: [Forge user privacy guide](https://developer.atlassian.com/platform/forge/user-privacy-guidelines/), independently retrieved HTTP 200 on 27 November; page last updated 30 October 2024. [Retrieval and SDK hashes](evidence/2026-11-27-privacy-research.json). Full article bytes remain in ignored private scratch, not this public repository.

The guide requires ALL apps storing personal data to report accounts and act on closed/updated outcomes, including apps using Forge storage/entity properties. Default cycle is seven days per account, not more frequently; an API Cycle-Period header overrides it. Maintain resumable iteration and additions/deletions. Use the OLDEST retrieval time across retained personal-data aspects, not the newest activity timestamp. Account IDs have 1–128 alphanumeric, hyphen or colon characters. Requests allow at most 90 accounts; 200 carries closed/updated actions, 204 no actions, 429 requires Retry-After delay. Scope report:personal-data is required.

Installed @forge/api 8.5.0 exposes privacy.reportPersonalData(accounts). Its implementation posts to the Atlassian-only /app/report-accounts endpoint, slices into 90-account requests, recursively dispatches larger input concurrently, maps 204 to [], and rejects non-200/204 responses. Crucially, it discards successful response headers, including Cycle-Period. Our <=90 bound prevents its recursive fan-out. The installed implementation is exercised with a fake platform transport; no real reporting endpoint was called.

**Activation blocker:** the public SDK does not expose the cycle override. Do not silently assume weekly reporting is compliant. Obtain a supported header-preserving Forge API contract or written Atlassian guidance before implementing/activating a durable scheduler. Do not bypass this through undocumented runtime internals, direct external fetch, non-Atlassian egress or owner credentials. No unsupported route is implemented here.
